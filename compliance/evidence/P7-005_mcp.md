# Evidência P7-005 — MCP.1 (IAP + DPA multi-constraint)

**Data:** 2026-08-08 (follow-up final)  
**Branch:** `feat/p7-ts-4010`  
**Task:** P7-005 — MCP.1 Rel1Ext §8.10.4.1

## Defeito observado

CPAS aplicava DPA movelist por omissão, mas IAP só corria com kwargs.
Follow-up: `collect_active_dpa_grants` lia a tabela viva de grants durante
CPAS, permitindo que a geração N+1 contaminasse a execução já congelada.

## Alterações

- `services/iap/protection_points.py` — pontos IAP a partir de injects
  (FSS/WISP/PPA/ESC); `IapThresholdProfile` local (não tabelas oficiais).
- `services/mcp_protection.py` — merge peer/IAP/DPA; skip IAP sem coupling.
- `services/cpas_service.py` — peer → IAP → DPA com EIRP efectivo; DPA recebe
  `grant_pks=snapshot.active_grant_pks` + peer FAD congelado.
- `services/dpa_protection.py` — coleta por PKs congelados; peers contribuem
  (`is_managing_sas=False`) sem mutação local; movelist persistido só com
  grants managing.
- `tests/unit/test_mcp_iap_dpa.py` — mix GAA/PAL, freeze N vs N+1, peer ownership.
- `tests/integration/test_cpas_multi_sas_postgres.py` —
  `test_postgres_dpa_collect_uses_frozen_local_pks`.

**Não claim:** `PASS_LOCAL` / `PASS_OFFICIAL` para `WINNF.REL1Ext.FT.S.MCP.1`
(status `failing`). Coupling IAP permanece injectável/ENV — ausência não
produz resultado RF “como ITM”. Thresholds do profile são locais.
